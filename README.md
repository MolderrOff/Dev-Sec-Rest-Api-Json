Реализация REST API на **.NET Core** для парсинга HTML, дешифрования AES-256-ECB, валидации и работы с PostgreSQL. Проект готов к развертыванию через Docker Compose.
Разработано в CLEAN-архитектуре

---

## 🚀 Быстрый запуск

1. Клонируйте репозиторий:
      ```bash
   git clone https://github.com
   cd Dev-Sec-Rest-Api-Json
   ```
2. Запустите проект:
   ```bash
   docker compose up --build
   ```

## Обоснование использования асинхронности в REST API 

### 1. Польза от использования асинхронных функций в REST API
Основная цель асинхронности в веб-сервере  — масштабируемость и высокая пропускная способность под высокой нагрузкой.

* Неблокирующий ввод-вывод (I/O Bound):** Когда веб-сервер получает запрос, поток из пула потоков (ThreadPool) выделяется на его обработку. Если внутри метода происходит синхронный запрос к БД (PostgreSQL) или скачивание страницы из сети, поток блокируется и «спит», ожидая ответа. В асинхронной модели с `async/await` поток освобождается на время ожидания внешнего ресурса и может обслуживать другие входящие HTTP-запросы.
* Экономия ресурсов:** Меньше заблокированных потоков означает меньшее потребление  памяти на стек потоков и отсутствие дорогостоящего переключения контекста  процессора.

---

### 2. Обоснование неиспользования асинхронных аналогов в некоторых местах

В некоторых участках кода  использование асинхронных методов нецелесообразно по следующим причинам:

#### А. Вычисления, привязанные к процессору (CPU-Bound операции)
* **Пример в проекте:** Расшифровка строки алгоритмом AES256-ECB.
* **Почему синхронно:** Криптографические операции нагружают исключительно CPU. Вызов `Task.Run` или попытка сделать этот метод асинхронным лишь создадут лишние накладные расходы (выделение памяти под объект `Task`, планирование задачи в ThreadPool). Потоки веб-сервера оптимизированы под быструю обработку CPU-задач "на месте", если они занимают миллисекунды.

#### Б. Ограничения используемых библиотек
* **Пример в проекте:** Парсинг HTML-строки в DOM-дерево с помощью `AngleSharp` (`new HtmlParser().ParseDocument(htmlString)`).
* **Почему синхронно:** Библиотека AngleSharp выполняет парсинг уже скачанной и находящейся в оперативной памяти строки. Это чисто процессорная операция (CPU-bound), у неё отсутствует реальный  ввод-вывод. Попытка обернуть её в асинхронный метод  замедлит выполнение .

#### В. Валидация данных
* **Пример в проекте:** Проверка входящей модели с помощью `FluentValidation` (`validator.Validate(model)`).
* **Почему синхронно:** Валидация структуры JSON (проверка на null, пустые строки) происходит в оперативной памяти процессора. Метод `ValidateAsync` во FluentValidation нужен только в тех редких случаях, когда правила валидации требуют обращения к внешним ресурсам (например, проверка уникальности Email через запрос к базе данных). В нашей задаче все проверки локальные, поэтому синхронный `Validate` работает быстрее.
